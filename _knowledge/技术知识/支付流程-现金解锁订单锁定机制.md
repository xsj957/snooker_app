# 现金解锁视频 — 支付业务文档

> **支付方式**：安卓 = 微信支付 | iOS = IAP 沙盒支付
> **核心规则**：待支付订单 30 秒窗口期，超时复用 1 次，再次超时锁单
> **微信分身**：系统级选择器，前后端均无法感知用户选择或取消

---

## 一、业务流程说明

### 1.1 正常支付流程

1. 用户在视频详情页点击「现金解锁」
2. 后端创建待支付订单（`pay_status = '待支付'`），开始 30 秒倒计时
3. 根据平台拉起支付：
   - **安卓**：拉起微信支付（若系统有分身，弹出系统分身选择器）
   - **iOS**：弹出 IAP 沙盒支付弹窗
4. 用户完成支付 → 后端收到支付回调 → 订单改为「支付成功」→ 视频解锁

### 1.2 取消支付流程（有回调）

- 用户在支付弹窗中主动取消（关闭弹窗）
- 前端收到取消回调 → 后端将订单改为「支付取消」
- **前提**：取消操作发生在 30 秒窗口期内
- 取消后允许用户立即重新下单

### 1.3 无回调超时处理（分身选择器关闭等场景）

安卓系统分身选择器、网络中断等场景下，前端收不到取消回调，订单卡在「待支付」。处理策略：

- **第 1 次超时**（30 秒无回调）：不锁定，允许用户复用原订单重新拉起支付
- **复用后仍超时**（再次 30 秒无回调）：锁定该视频 **30 分钟**
- 锁定期内用户点击该视频解锁，提示「该视频暂时无法解锁，请稍后再试」
- 锁定到期后自动解除，用户可重新下单

### 1.4 防刷限制

- 同一用户并发待支付订单数上限：**3 个**（防止批量点击不同视频占用订单）
- 同一视频同时只能有 1 个待支付订单

## 二、优化前后对比

### 订单锁定机制

| 对比项 | 优化前 | 优化后 |
|--------|--------|--------|
| 第 1 次超时处理 | 直接锁定 2 小时 | 给 1 次复用机会，重新拉起支付 |
| 第 2 次超时处理 | —（已锁） | 锁定 30 分钟 |
| 锁定期时长 | 2 小时 | 30 分钟 |
| 分身用户影响 | 关闭系统选择器即被锁 2 小时 | 可复用订单继续支付，仅反复超时才锁 30 分钟 |
| 防刷能力 | 强（每视频 2h 内 1 单） | 强（复用限 1 次 + 并发上限 3 单） |

### 用户体验对比

| 场景 | 优化前 | 优化后 |
|------|--------|--------|
| 正常支付成功 | ✅ 视频解锁 | ✅ 视频解锁（不变） |
| 主动取消（有回调） | ✅ 可重新下单 | ✅ 可重新下单（不变） |
| 关闭分身选择器（无回调） | ❌ 锁 2 小时，无法操作 | ⚠️ 给 1 次重试机会 |
| 重试后仍无回调 | — | ❌ 锁 30 分钟 |
| 被竞品批量刷单 | ✅ 锁 2h 防刷 | ✅ 并发上限 3 单防刷 |

## 三、完整流程（文字版）

```
用户点击现金解锁
  │
  ├─ 视频被锁定？── 是 ──→ 提示"暂时无法解锁" ──→ 结束
  │
  └─ 否 ─→ 创建待支付订单（30秒倒计时）
                │
                ├─ 支付成功回调 ──→ 订单"支付成功"，视频解锁 ✅ ──→ 结束
                │
                ├─ 取消回调(≤30秒) ──→ 订单"支付取消"，可重新下单
                │
                └─ 无回调超时(>30秒)
                      │
                      ├─ 第1次超时 ──→ 复用原订单，允许再次支付（30秒）
                      │                    │
                      │                    ├─ 支付成功 ──→ ✅ 结束
                      │                    ├─ 取消回调 ──→ 订单"支付取消"，可重下
                      │                    └─ 再次超时 ──→ 锁定30分钟 ❌ ──→ 结束
                      │
                      └─ 已有复用记录 ──→ 锁定30分钟 ❌ ──→ 结束
```

## 四、订单状态

| 状态 | 说明 | 后续操作 |
|------|------|---------|
| 待支付 | 订单已创建，等待用户支付 | 30秒内取消可重下；第1次超时复用1次；再次超时锁30分钟 |
| 支付成功 | 支付完成，视频已解锁 | 视频可观看 |
| 支付取消 | 用户在 30 秒窗口期内主动取消 | 可立即重新下单生成新订单 |

---

## 五、关键字段

| 字段 | 说明 |
|------|------|
| `pay_status` | 支付状态：待支付 / 支付成功 / 支付取消 |
| `pay_channel` | 支付渠道：2 = App-Android(微信)，3 = App-iOS(IAP) |
| `transaction_id` | 微信/IAP 交易流水号。**有值** = 现金解锁；**空** = 视频券解锁 |
| `combo_order_id` | NULL 或 0 = 现金解锁；大于 0 = 视频券解锁（关联 `video_combo_order.id`） |
| `refund_status` | 退款状态：0=未退款, 1=已申请, 2=已退款, 3=退款失败 |

## 六、已知设计缺陷

| 缺陷 | 场景 | 影响 | 建议 |
|------|------|------|------|
| 分身选择器无回调 | 安卓系统分身选择器关闭，前后端均无法感知 | 订单卡待支付，需依赖超时复用机制兜底 | 后端增加复用机制（本文档优化方案） |
| 无订单管理入口 | App 内无订单管理页面 | 用户无法查看和清理待支付订单 | 增加订单管理入口或待支付订单提示 |
