## 编写规则

1. **用例标题**：必须包含预期结果，阅读标题即可知道该用例验证什么
   - ✅ `微信授权成功后自动登录并同步小程序数据`
   - ❌ `测试微信登录`
2. **步骤与预期一一对应**：步骤N对应预期结果N，**条数必须完全相同**
3. **前置条件独立**：不混入操作步骤
4. **优先级划分**：P0=阻塞性 P1=影响体验 P2=边界/UI
5. **一条用例一个验证点**：不合并多个验证目标
6. **编号连续**：新增用例分配到下一个可用的连续编号，不使用子编号（禁止 TC-XXX-1 格式）
7. **Section 归属**：新增用例必须插入到对应功能模块的 Section 内，**禁止追加到文件末尾或其他无关 Section 下**
8. **行高自适应**：每行 TC 的行高必须根据内容条数自动计算，公式为 `max(25, 条数*18pt)`
9. **垂直居中**：每个单元格必须设置垂直居中（vertical=center）

## 冒烟测试规范

放在独立 Sheet「冒烟测试」中，编号 SM-001 起连续编排。

**冒烟测试列结构（20列，与普通用例列结构一致）**：

| 列 | 列名 | 说明 |
|----|------|------|
| A | 用例编号 | SM-XXX 格式 |
| B | 测试系统 | 系统名称（如"斯诺克大师国内APP"） |
| C | 测试模块 | 冒烟测试 |
| D | 测试类型 | 功能（冒烟仅考虑功能性） |
| E | 测试场景 | 冒烟测试场景分类（如"支付主流程"、"分享主流程"） |
| F | 用例标题 | 必须突出预期结果 |
| G | 前置条件 | 执行用例前的必要状态 |
| H | 操作步骤 | 按序号列举 |
| I | 预期结果 | 按序号对应操作步骤 |
| J | 优先级 | 全部 P0 |
| K–M | sit1执行结果/执行时间/测试人员 | 同普通用例 |
| N–P | sit2执行结果/执行时间/测试人员 | 同普通用例 |
| Q–S | uat执行结果/执行时间/测试人员 | 同普通用例 |
| T | 备注 | 补充说明 |

**编写原则**：
1. 按需求维度覆盖，端到端主流程优先
2. **冒烟测试只考虑功能性**，不涉及性能/兼容/UI类型，确保主流程不阻塞即可
3. **冒烟测试用例不受步骤数量限制**（可超过12步），一条用例可覆盖完整主流程
4. 全部P0优先级
5. 步骤与预期严格一一对应

## 两平台同步规则

- 安卓/国内iOS 两个 Sheet 的测试用例需保持同步
- 需求不区分平台的功能（视频制作、播放器等），两个 Sheet 用例内容完全一致
- 按地区区分的功能（登录方式、支付等），各 Sheet 写各自平台的用例
- 海外App暂不纳入测试范围

## Excel 表格格式规范

**TC 行样式**：字体微软雅黑 10pt，背景色 FFFCE4EC，边框 thin，垂直居中 + 自动换行

**Section Header 样式**：微软雅黑 10pt 加粗，白色字体，深蓝背景 FF2F5496，**合并 A:J 列**

**执行结果列（K、N、Q 列）**：
- 下拉选项：通过 / 失败
- 条件格式：通过→浅绿+深绿粗体，失败→浅红+深红粗体
- 预设范围 K2:K10000（sit1）、N2:N10000（sit2）、Q2:Q10000（uat），新增用例自动带上下拉和颜色联动

**测试人员列（M、P、S 列）**：
- 下拉选项：张梓聪 / 谢仕杰 / 邹德乾
- 预设范围 M2:M10000（sit1）、P2:P10000（sit2）、S2:S10000（uat）

## 用例生命周期管理

### 核心修复

`insert_rows` / `delete_rows` 不调整合并范围，操作前必须取消所有合并，操作后重新合并。

### Excel 操作用 `/test-case-ops` skill

涉及 insert_rows / delete_rows 等 Excel 操作时，必须使用 `/test-case-ops` skill 中的代码模板。

### 新增用例

1. 找到目标 Section 内按功能逻辑应插入的位置
2. 新用例编号 = 该位置原用例的编号
3. 原位置及后续所有用例编号依次 +1

### 删除用例

1. 删除目标行
2. 后续所有 TC 编号 -1
3. 重新合并所有 Section

### 修改用例

- 直接修改目标单元格内容
- **不改变编号**（除非修改导致用例归属 Section 变化）

### 批量变更顺序

1. **先删除** → 重新编号
2. **再修改** → 调整内容
3. **最后新增** → 插入并重新编号

### 操作后必须验证

- [ ] 新行无合并单元格
- [ ] 后续行内容完整（场景、标题不为空）
- [ ] Section Header 合并正确
- [ ] 编号连续无断号
- [ ] 样式与已有行一致

### 文件保存

- 每次操作后生成**带时间戳的新文件**，命名格式：`测试用例-YYYYMMDD_HHMM.xlsx`（如 `测试用例-20260830_1530.xlsx`）
- 不再使用 `_temp` 后缀，直接输出独立文件，避免 WPS 锁定冲突
- 在脚本中通过 `datetime.now().strftime('%Y%m%d_%H%M')` 生成时间戳
