# 三、核心业务流程

## 3.1 用户端到端流程（总览）

斯诺克大师App的核心业务流程围绕"视频"展开，用户从比赛结束到视频分享的完整流程如下：

```
比赛结束 → 工控机生成视频列表 → 用户打开App → 浏览交手记录
    ↓
解锁视频（使用视频券/付费）→ 视频状态变为"已解锁"
    ↓
工控机裁切原片并上传腾讯云 → App下载原片到本地
    ↓
App本地制作视频（叠加比分、头像、特效）→ 制作完成
    ↓
视频保存到App缓存/相册 → 用户使用专业播放器观看
    ↓
分享视频到社交平台（第二期）/ 保存到相册
```

### 关键节点说明

**节点1: 比赛结束与视频生成**
- 用户在俱乐部使用计分系统进行斯诺克比赛
- 比赛结束后，工控机自动生成本场比赛可解锁的视频列表
- 视频类型包括：单杆视频、局视频、精彩集锦、失误集锦

**节点2: 用户打开App浏览**
- 用户打开App，进入首页或交手记录页
- 系统显示用户的比赛记录和可解锁视频
- 视频卡片显示状态：待解锁/下载中/制作中/已解锁

**节点3: 解锁视频**
- 用户点击"解锁视频"按钮
- 系统判断使用视频券还是付费解锁
- 解锁成功后，视频状态变为"已解锁，等待上传"

**节点4: 原片下载与制作**
- 工控机收到指令，裁切原视频片段并上传至腾讯云
- App从腾讯云下载原片到本地（最大并发2个）
- 下载完成后，App自动开始本地制作

**节点5: 视频完成与观看**
- 制作完成后，视频保存到App本地缓存
- 如用户授权相册权限，同时保存到用户相册
- 用户使用专业播放器观看视频

**节点6: 视频分享**
- 第一期：仅支持保存到相册
- 第二期：支持分享到微信、朋友圈、抖音

## 3.2 视频制作全流程（核心）

视频制作是本App的核心功能，将视频制作从工控机转移到用户手机本地，大幅提升制作速度和用户体验。

### 3.2.1 制作流程详解

```
┌─────────────────────────────────────────────────────────┐
│                    视频制作完整流程                        │
└─────────────────────────────────────────────────────────┘

[用户点击解锁视频]
        ↓
[系统判断制作方式]
   ├─ 满足本地制作条件 → App本地制作
   └─ 不满足条件 → 工控机制作（降级）
        ↓
[App本地制作流程]
        ↓
步骤1: 解锁成功
   - 更新视频状态为"已解锁，等待上传"
   - 弹窗询问相册权限
   - 同步状态到小程序（文案：制作中，请至App内查看）
        ↓
步骤2: 工控机上传原片
   - 裁切原视频片段
   - 上传至腾讯云
   - 上传素材数据（比分、头像、时间戳等）
   - 更新状态为"原片已上传"
        ↓
步骤3: App下载原片
   - 检测手机剩余空间（≥视频大小+200MB）
   - 从腾讯云下载原片
   - 下载视频信息（比分、头像等）
   - 更新状态为"下载中"
        ↓
步骤4: 本地制作
   - 视频压缩处理（720P）
   - 叠加片头片尾、俱乐部名称
   - 叠加用户头像、昵称、比分条
   - 叠加Logo和特效（集锦类）
   - 更新状态为"本地制作中"
        ↓
步骤5: 制作完成
   - 视频保存到App本地缓存
   - 如授权相册，自动保存到相册
   - 更新状态为"制作完成"
   - 视频卡片显示NEW标记（未播放前）
   - 同步状态到小程序（文案：制作成功，请至App内查看）
```

### 3.2.2 视频状态机（9种状态）

视频制作过程中，视频会经历9种状态，每种状态对应不同的UI展示和业务逻辑。

| 状态值 | 状态名称 | 说明 | 小程序同步文案 |
|--------|----------|------|----------------|
| 0 | 待解锁 | 比赛结束后可解锁的视频 | 未明确（推测沿用现有样式） |
| 1 | 已解锁等待上传 | 用户已解锁，等待工控机上传原片 | 制作中，请至App内查看 |
| 2 | 原片已上传 | 工控机已将原片上传至腾讯云 | 未明确（推测沿用现有样式） |
| 3 | 下载中 | App正在从腾讯云下载原片 | 制作中，请至App内查看 |
| 4 | 下载失败 | 原片下载失败（网络/文件丢失） | 制作失败，请至App内查看 |
| 5 | 本地制作中 | App正在进行视频制作 | 制作中，请至App内查看 |
| 6 | 制作失败 | 视频制作失败（素材丢失/空间不足） | 制作失败，请至App内查看 |
| 7 | 制作完成 | 视频制作完成，可播放 | 制作成功，请至App内查看 |
| 8 | 已过期 | 视频已过期（48h未解锁/90d未制作/缓存清除） | 已过期 |

**状态流转规则**:
```
待解锁(0) → 已解锁等待上传(1) → 原片已上传(2) → 下载中(3) → 本地制作中(5) → 制作完成(7)
                                                              ↓
                                                         下载失败(4) / 制作失败(6)
```

**过期规则**:
- 视频48h内未解锁 → 已过期(8)
- 原视频片段下载后90d内未制作 → 已过期(8)
- 视频在App本地缓存被清除 → 已过期(8)（小程序显示"制作成功"）

### 3.2.3 制作方式判断逻辑

用户点击"解锁视频"后，系统按以下规则判断制作方式：

```
[用户点击解锁视频]
        ↓
[检测当前设备是否满足本地制作条件]
   ├─ iOS系统 ≥ iOS 15
   ├─ Android系统 ≥ 安卓10.0
   ├─ 手机剩余空间 ≥ 视频大小 + 200MB
   └─ 其他硬件条件
        ↓
   ┌─ 满足条件 → 走App本地制作流程
   └─ 不满足条件 → 自动切换为工控机制作流程
```

**工控机制作流程**（低版本手机或设备不满足条件时）:
- 视频制作由工控机完成
- App端无"下载中"、"本地制作中"状态
- 仅有原工控机的"制作中"状态
- 制作完成后，视频上传至腾讯云，App从腾讯云下载成品视频

### 3.2.4 任务队列管理

**下载任务**:
- 同时最大下载数：2个
- 任务队列优先级：下载任务 > 制作任务
- 下载前检测手机空间，不足时提示"手机可用存储空间不足"

**制作任务**:
- 自动制作触发页面（4个）:
  1. 首页
  2. 交手记录页
  3. 场详情页
  4. 我的视频页
- 用户进入以上页面时，系统查询是否有已下载完成的视频
- 如有，自动开始制作

### 3.2.5 异常处理机制

#### 场景1: 原片下载失败

**原因1: 用户网络异常或杀掉App**
- 网络恢复 + App在前台时，自动重试（静默）
- 弹出弹窗询问："你有X个制作中断的视频，是否继续制作？"
  - 点击"继续制作": 跳转到我的视频-制作中页面，自动重新开始下载
  - 点击"暂不": 弹窗关闭，视频显示为"制作中断状态"

**原因2: 云端文件丢失**
- 视频显示为"下载失败"状态
- 自动退券至用户账户（返还有效期）
- 或显示下载失败，支持用户手动申请退款
- 同步状态到小程序（文案：制作失败，请至App内查看）

#### 场景2: 本地制作中断

**原因: 用户杀掉App或App未保持在前台**
- 用户下次启动App时，自动继续/重新制作
- 弹出弹窗提示："你有X个制作中断的视频，是否继续制作"
  - 点击"查看": 跳转到我的视频-制作中页面，视频自动重新开始制作
  - 点击"暂不": 弹窗关闭，视频显示为"制作中断状态"
- 弹窗优先级：最高（在活动弹窗之前，关闭后活动弹窗出现）

#### 场景3: 本地制作失败

**原因1: 素材、数据丢失**
- 视频显示为"制作失败"状态
- 自动退券至用户账户（返还有效期）
- 或显示制作失败，支持用户手动申请退款
- 同步状态到小程序（文案：制作失败，请至App内查看）

**原因2: 手机空间不足**
- Toast提示："手机可用存储空间不足，视频制作已终止"
- 终止制作任务
- 英文提示："Insufficient storage space on your device."

#### 自动退券机制

**退券条件（系统原因）**:
- 腾讯云文件丢失
- 素材数据丢失
- 自动退券至用户账户，返还有效期

**不退券条件（用户原因）**:
- 用户断网
- 用户杀掉App
- 保留任务 + 弹窗恢复

**模拟自动退券方式**:
- 制作阶段：等下载完成后清除App缓存 → 重进App触发制作 → 素材丢失 → 自动退券
- 下载阶段：需开发配合（使用失效URL）

## 3.3 账号数据同步流程（小程序↔App）

### 3.3.1 同步机制

App端微信登录与小程序登录的账号打通，依赖微信开放平台（Open Platform）的UnionID机制。

**UnionID机制说明**:
- 用户在同一微信开放平台下的不同应用（小程序、App）拥有相同的UnionID
- 后端通过UnionID关联用户身份，实现数据同步

**同步触发时机**:
- 用户首次微信登录App时，自动同步小程序端所有数据
- 后续登录时，增量同步新增数据

### 3.3.2 同步数据范围

| 数据类型 | 同步内容 | 说明 |
|----------|----------|------|
| **比赛数据** | 历史比赛列表、比赛成绩、比赛详情 | 用户的所有比赛记录 |
| **个人数据** | 用户昵称、头像、默认俱乐部设置 | 用户个人信息 |
| **视频券数据** | 可用视频券列表、已过期&已使用视频券 | 用户的视频券资产 |
| **视频数据** | 已解锁、制作中、已过期、制作失败的视频 | 用户的视频资产 |

**注意**:
- 仅微信登录与小程序同步数据
- Apple/Google/Facebook登录仅App内数据，不涉及与小程序同步

### 3.3.3 视频状态同步

App端的视频状态会同步到小程序端，小程序端显示统一的文案提示用户到App内查看。

| App端状态 | 小程序端文案 |
|-----------|--------------|
| 已解锁等待上传(1) | 制作中，请至App内查看 |
| 下载中(3) | 制作中，请至App内查看 |
| 本地制作中(5) | 制作中，请至App内查看 |
| 下载失败(4) | 制作失败，请至App内查看 |
| 制作失败(6) | 制作失败，请至App内查看 |
| 制作完成(7) | 制作成功，请至App内查看 |
| 已过期(8) | 已过期 |

**注意**: 小程序只展示5种文案：
- 制作中，请至App内查看
- 制作失败，请至App内查看
- 制作成功，请至App内查看
- 已过期
- （待解锁状态未明确）

### 3.3.4 账号注销同步

App端注销的微信账号，下次在小程序调用接口时：
- 返回【该账号已注销】的Toast提示
- 刷新小程序为未登录状态
